#Bank Account Management System

You have to build a **Bank Account Management System**.

There will be a base class called `BankAccount`. Each account must have a **unique account number**, which will be automatically generated by the system when the account is created. The user can only **read** the account number and must never be able to set or change it directly.

Each account will have an **owner name**. The user can read the owner name and update it later. However, whenever the owner name is updated, it must be validated to ensure that:

* It is not an empty string.
* It does not contain any digits (`0-9`).

If the validation fails, a `BankError` must be thrown.

Each account will have a **balance**, which initially starts at `0`. The balance should be **read-only** for the user (as a property). The user must not be able to directly set or change the balance. If someone tries to set it, it should either have no effect or throw an error.

Whenever a new account is created, the system's **total account count** should increase by `1`. This count must be shared among all accounts and accessible through the class, but it must not be directly changeable from outside the class.

### `BankAccount` Methods

The `BankAccount` class must contain the following methods:

* `deposit(amount)`
  Validate that the amount is positive, add it to the balance, and return the account itself so that multiple deposits can be chained.

* `withdraw(amount)`
  Validate that:

  * The amount is positive.
  * There is sufficient balance.

  Then subtract the amount from the balance and return the account itself so that method chaining is possible.

* `getAccountInfo()`
  Return a readable string containing the account's information.

### Static Factory Method

The `BankAccount` class must also have a static factory method:

```js
BankAccount.create(ownerName, initialDeposit = 0)
```

This method must:

* Validate the `initialDeposit`.
* Ensure that `initialDeposit >= 0`.
* Create and return a new account.

### Custom Error

Create a custom error class called `BankError` that extends the built-in `Error` class.

Its `name` property must be:

```js
"BankError"
```

All validation errors throughout the system must throw a `BankError`.

---

## Subclass: `SavingsAccount`

Create a `SavingsAccount` class that extends `BankAccount`.

It must have an **interest rate**, which is passed through the constructor. The default interest rate should be:

```js
0.05
```

It must contain the following method:

* `addInterest()`
  Calculate interest based on the current balance and add it to the balance.

`SavingsAccount` must also **override** `getAccountInfo()` so that the returned information includes the interest rate.

---

## Subclass: `CurrentAccount`

Create a `CurrentAccount` class that extends `BankAccount`.

It must have an **overdraft limit**, which is passed through the constructor. The default overdraft limit should be:

```js
1000
```

It must override the `withdraw()` method.

Unlike a normal `BankAccount`, a `CurrentAccount` is allowed to have a **negative balance**. However, the negative balance must never exceed the specified overdraft limit.

If a withdrawal would cause the negative balance to exceed the overdraft limit, a `BankError` must be thrown.

`CurrentAccount` must also override `getAccountInfo()`.
